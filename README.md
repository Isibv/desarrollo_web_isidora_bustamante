# Tarea 2 - ActividaDcc

Para el desarrollo de esta tarea se utilizó como base el prototipo realizado en la Tarea 1, manteniendo la misma estructura visual y las distintas secciones previamente definidas. A partir de este prototipo se implementó una aplicación utilizando Python con Flask y una base de datos MySQL mediante SQLAlchemy, buscando mantener una estructura simple y ordenada.
La aplicación se estructuró utilizando un archivo principal `app.py`, el cual contiene las distintas rutas y lógica de la página web. Además, se utilizaron carpetas separadas para los archivos HTML (`templates`), JavaScript y CSS (`static`) para mantener una mejor organización del proyecto.
En la portada principal se agregó un menú de navegación hacia las distintas funcionalidades del sistema, además de mostrar automáticamente los últimos miembros registrados desde la base de datos. Esta información se obtiene mediante consultas utilizando SQLAlchemy.
En la sección de registro de miembros se mantuvo gran parte de la lógica de la tarea anterior, incluyendo el uso de JavaScript para mostrar u ocultar campos dependiendo del tipo de miembro seleccionado (estudiante, académico o funcionario). Se implementaron validaciones tanto en JavaScript como en Flask para verificar datos como formato de RUT, correo electrónico y celular antes de realizar el almacenamiento en la base de datos.
Para el registro de actividades se implementó un formulario que permite asociar actividades a miembros registrados. En esta sección también se agregaron validaciones en JavaScript y validaciones básicas en el servidor utilizando Flask. Además, se incorporó la posibilidad de adjuntar archivos asociados a la actividad, los cuales son almacenados dentro de la carpeta `static/uploads`. Para evitar problemas con nombres de archivos se utilizó `secure_filename`.
La información de miembros y actividades es almacenada en tablas MySQL utilizando SQLAlchemy. Se trabajó principalmente con las tablas `miembro`, `actividad` y `foto`, además de registrar automáticamente la fecha de ingreso de cada miembro mediante la columna `fecha_registro`.
En la sección de listado de miembros se reemplazaron los datos estáticos de la tarea anterior por información obtenida directamente desde la base de datos. Se mantuvieron los filtros y ordenamientos desarrollados previamente con JavaScript para facilitar la visualización de la información.
La sección de estadísticas se dejó de manera simple, considerando que según el enunciado esta parte quedará pendiente para una próxima tarea. Por esta razón solamente se mantuvo una visualización básica de gráficos.
Durante el desarrollo, una de las partes que presentó más dificultades fue la conexión entre Flask y MySQL, además del manejo de formularios, rutas y almacenamiento de archivos. También se realizaron varias pruebas relacionadas con validaciones y funcionamiento de las consultas a la base de datos.
Finalmente, se priorizó el correcto funcionamiento del sistema y el cumplimiento de los requerimientos solicitados por sobre el diseño visual, manteniendo una interfaz simple y ordenada.
